# Snapline for Windows

<img src="src/Snapline.Windows/Assets/snapline.png" width="88" alt="Original Snapline icon">

**截图，挂在屏幕顶部。需要时出现，不需要时收起。**

灵感来源于 [alejandrobujan/tendedero](https://github.com/alejandrobujan/tendedero)。
这是独立的 Windows 原生实现，不是原作者发布的 Windows 版，也不与原作者关联。
原项目使用 Swift/AppKit；本项目使用 C#、.NET 10、WPF 和 Windows API。
遵守上游许可的名称/图标限制，使用独立名称 **Snapline** 和原创图标。

## 使用

**[下载 Windows x64 免安装版](https://github.com/ThousandOfWind/snapline-windows/releases/latest)** — 解压 ZIP 后运行 `Snapline.exe`。

- Windows 10/11，当前开发版 **0.1.12**（公开 Release 仍为 v0.1.11）。
- 本地免安装程序：`artifacts\Snapline-win-x64\Snapline.exe`。
- 可分发压缩包：`artifacts\Snapline-win-x64.zip`。解压后运行 `Snapline.exe`。
- 自包含包不要求预先安装 .NET，不需要管理员权限。
- 启动后直接展开截图栏，明确显示已运行；收起后驻留系统托盘（可能在任务栏的 `^` 隐藏图标中）。
- 再次双击 EXE 会唤出已有实例，不会静默退出，也不会启动第二个后台进程。
- 截图栏无整块底板，卡片间完全透明；收起后右上角保留小入口，点击即可找回。
- 内置截图成功或取消后自动恢复并保持展开，直到主动收起，不会截完图立即消失。
- 手动/快捷键/入口展开保持固定；只有鼠标悬停自动展开的栏会在移开后自动收起。
- 拖动左侧 **Snapline / 拖动移动** 标签移动截图栏；按住收起的小入口也可移动。两者分别保存位置，重启恢复。
- 图片拖拽会显示鼠标旁跟手的照片预览，原卡片变淡、暂时松开夹子；松开/Esc 后恢复。
  Windows 的复制/禁止放置光标保留，预览不拦截目标窗口；拖拽仍只复制文件，不删除源图。
- 第一次移动时，全宽截图栏变成最多 960 DIP 的浮动栏，便于横向移动；透明样式和卡片横向滚动不变。
- 拖动限制在显示器工作区内，避免移出屏幕；托盘菜单 **重置组件位置** 可恢复默认位置。
- 悬挂物材质区分：图片是暖白相纸框＋木夹，软件窗口是蓝灰标题条框＋银色夹，识别到的资源管理器窗口是文件夹标签框＋黄铜夹。
- Hover：卡片被轻碰后绕夹子来回摆动并自然停稳，不放大、不保持僵硬倾斜。
- 收起入口的绳子和夹子固定，小照片与数量标签分别响应；按钮轻抬，按下压缩、松开回弹。
- 使用保留当前位置/速度的有限弹簧曲线，快速进入/移出不会突跳；拖动时停止动效。
- 默认跟随 Windows 的动画设置。系统动画关闭但想体验动效时，可在托盘主动勾选 **启用动画（即使系统已关闭）**，
  并保持 **减少动画** 未勾选。此选项只影响 Snapline，不修改 Windows 设置；“减少动画”优先。
- 未签名，Windows SmartScreen 可能显示发布者未知。仅在确认来源后按组织安全策略运行；不要关闭系统保护。
- 不自动安装、不设置开机启动、不修改 Windows 截图位置或快捷键。

| 操作 | 功能 |
|---|---|
| `Ctrl+Alt+T` | 显示 / 隐藏截图栏 |
| `Ctrl+Alt+S` | 区域截图；拖动选择，`Esc` 取消 |
| 鼠标在屏幕顶部停留约半秒 | 临时展开已有截图；移开后自动收起 |
| 点击“迷你照片 + N 张”小入口 | 找回截图栏并保持展开 |
| 拖动左侧 `Snapline / 拖动移动` | 移动整个截图栏，松开保存位置 |
| 按住迷你照片入口拖动 | 移动收起的小入口；不触发展开 |
| 托盘“重置组件位置” | 恢复顶部截图栏和默认右上角入口 |
| 单击托盘图标 | 显示截图栏并保持展开 |
| 单击缩略图 | 复制完整图片和文件引用 |
| 双击缩略图 | 内置预览，`Esc` 关闭 |
| 拖拽到资源管理器或接受文件的应用 | 发送文件副本，原文件仍保留 |
| 右键缩略图 → 编辑 / 标注 | 打开内置图片编辑器；预览页也提供编辑入口 |
| 点击 `×` | 从栏中移除图片，**不删除原文件** |
| 把栏内截图拖到另一张截图上 | 松手形成截图组 |
| 把截图 / 截图组拖到组卡片上 | 加入 / 合并成同一个截图组 |
| 点击组或“展开组” | 展开单张成员；再点“收起组”折叠 |
| 拖动组卡片 / 右键“复制整组图片文件” | 一次导出 / 复制全部图片文件 |
| 将软件标题栏拖到整条晾衣绳 | 靠近显示空夹子和“松手挂上”，松手即最小化并挂上窗口卡片，无需等待 |
| 点击“窗口暂存”卡片 | 取回同一个运行中的窗口，恢复原位置 |
| 托盘“取回全部暂存窗口” | 恢复所有仍存活的窗口，不重启软件 |
| 托盘菜单 | 导入图片、区域截图、监听目录、可选剪贴板监听、退出 |

最多保留 50 个文件引用，超出时移除最旧引用，原文件不删除；可横向滚动。
重启恢复栏中记录。PNG/JPEG/BMP/GIF/TIFF 可用，WebP 取决于系统 WIC 解码器。
动图只显示静态帧。图片文件被移动或删除后，栏中引用会自动清理。

### 内置图片编辑 / 标注（0.1.12）

入口：截图卡片（含展开组内单张）右键 **编辑 / 标注…**，或双击预览后点 **编辑 / 标注**。

- **画笔、高亮、箭头、矩形框、圆框、文字、裁剪、马赛克、不透明遮挡**。
- 选择颜色和线宽；文字先在工具栏输入，再点图片放置，字号随线宽调整。
- 拖动裁剪框后松手裁剪；逆向拖动可用，Esc 取消当前手势；Ctrl+Z 撤销、Ctrl+Y 重做（最多 100 步）。
- 支持缩放和“适应窗口”；编辑与导出使用原始像素，未裁剪时不因窗口缩小而降低分辨率。
- **完成并挂回**（或 Ctrl+S 保存）：在 Snapline 收件箱生成新 PNG 副本；关闭编辑器后副本加入栏。
- **另存 PNG…**（Ctrl+Shift+S）：选择新文件名。原图和已有文件均不自动覆盖。
- **复制结果**：复制当前裁剪/标注后的 raster 图片；复制不等于保存，关闭未保存编辑会确认。
- 导出是扁平 PNG，无本次可编辑图层或原图载荷。马赛克不保证内容无法推断；敏感信息请用 **遮挡**，且分享编辑后的副本，不要分享仍保留的原图。
- 从组内编辑同样保存独立副本，不替换原组成员；可再手动把副本加入组。
- 首版不支持旋转、缩放输出像素、JPEG 压缩、选中/移动已有标注或图层工程保存；误画用撤销重画。
- 编辑上限：64M 像素、200 个标注、20 个马赛克区域；超限不提交，不请求网络服务或安装外部编辑器。

### 截图组（0.1.11）

- 在 Snapline **栏内**，把一张图拖到另一张图上，边框提示“松手创建截图组”，松手后变成叠放照片＋数量＋浅紫宽夹。
- 继续拖图片到组上可加入，组拖到另一组可合并；同一张图只属于一个组，不生成嵌套组。
- 点击组卡片或“展开组”查看各张图片；展开后仍可复制、预览、拖出单张。
- 拖动**组卡片本身**带出全部成员，跟手预览显示数量。右键复制整组、解散组；子图右键可“移出截图组”。
- 组成员/ID 保存在本地设置，兼容旧设置；图片被移除/淘汰/删除时清理分组，剩一张则还原为单图。
- 合组/解散/移出只修改引用，不移动或删除文件。图片总容量仍按成员数量计算。
- **整组复制是多个文件引用，不是多张 bitmap 或拼接长图**。资源管理器等支持多文件的目标可一次接收；聊天/编辑器是否接收多张取决于目标应用。
- 首版只接收本次 Snapline 会话内部图片拖拽来合组，外部文件拖入仍不自动导入/分组；软件窗口不参加截图组。
- 取消拖拽不改变分组；同组自拖无操作。真实物理 OLE 拖放和跨应用多文件兼容仍需验收。

### 软件窗口暂存（0.1.10：Explorer 兼容改进）

1. 按住支持的软件**标题栏**拖动，Snapline 会自动展开晾衣绳，无需找收起的小照片入口。
2. 把鼠标带到**绳子任意位置附近**：绳子轻轻下沉并亮起，出现空夹子和 **松手挂上窗口**。
3. **松手即挂上**：原软件被最小化，绳子上出现窗口卡片，**没有等待时间**。
4. 点击该卡片取回同一个窗口，恢复拖入前的位置/最大化状态，继续使用原来的内容。

一直按住不会自动暂存；移开绳子、松手在别处或 Esc 取消不提交。
收起时右上角的迷你照片仍是普通点击入口，但暂存软件主要用整条绳子。
如果 Windows 边缘吸附抢占手势，可以先把晾衣绳组件拖到桌面中间再尝试。
窗口卡片不支持当图片复制/导出，不混淆“移动组件”和“暂存软件”。
可在托盘关闭 **拖入软件窗口暂存**，或使用 **取回全部暂存窗口**。

如果 File Explorer 仍然不能挂上：右键托盘 → **窗口暂存诊断…**，反馈里面的那一句提示即可，
不用截图或提供你的文件列表。0.1.10 支持自绘标题区 `HTCLIENT`、子窗口事件归一化，并增加
标题区域＋窗口跟手位移的兜底识别；松手检测兼容事件早于按钮状态更新的短暂时序。
真实 Explorer 验证仍未完成：空目录探针不能可靠定位新窗口，未检查既有私人窗口来代替验证。

**安全边界与限制：**

- 不关闭软件、不结束进程、不把窗口藏到任务栏之外，不重新打开软件或文件。
- 即使 Snapline 退出/崩溃，软件仍是普通的最小化窗口，随时可从任务栏/Alt+Tab 取回。
- 窗口卡片仅在当前 Snapline 会话有效，**不保存 HWND 到磁盘**，不支持关机/重启后的应用会话恢复。
- 最多 20 个窗口；满了拒绝新暂存，不自动移除/关闭已有窗口。软件关闭后卡片自动清理。
- 用进程身份和窗口生命期标记验证原窗口，避免过期 HWND 被复用后唤出别的软件。
- 只显示你主动拖入窗口的标题/软件图标；不截取内容，不把标题写入设置/日志。
- 监听标准 Windows 标题栏移动事件，只接受可最小化的普通顶层窗口。调整大小、窗口主体重叠、
  短暂经过、Esc 取消不应触发。子窗口、弹窗、系统桌面/任务栏和 Snapline 自身不接收。
- 不支持高权限软件，不请求提权或绕过 Windows 前台限制。若不能切前台，窗口仍恢复，需点击任务栏。
- 首版已用合成窗口验证最小化/取回及事件处理；真实第三方标题栏、独占全屏、Windows 吸附和多屏/DPI
  组合仍需试用，自绘标题栏可能不发标准事件。

### Windows 自带截图

默认监听系统 Pictures 目录下的 `Screenshots` / `屏幕截图`（存在时）。
如果截图位于 OneDrive 或其他工具的自定义目录，用托盘里的 **添加监听目录** 选择真实目录。
只监听所选目录新建/更新的图片，不扫描或导入历史内容，不递归子目录。
可在 **管理监听目录** 停止监听。

`Win+Shift+S` 是否保存文件取决于截图工具设置。若只复制到剪贴板，需要手动开启
**监听剪贴板图片**；也可以直接用 `Ctrl+Alt+S`，由 Snapline 保存区域截图。

### 隐私和数据

- 应用本身无网络请求、账号、遥测或云服务。构建工具/包下载和 GitHub CI 不是应用运行时。
- 设置和记录：`%LOCALAPPDATA%\Snapline\settings.json`。
- 内置截图/剪贴板图片：`%LOCALAPPDATA%\Snapline\Inbox`。
- 剪贴板监听**默认关闭**。开启后只处理图片，跳过同时带文本或文件、以及已知隐私/密码管理器标记的内容。
  无标记的敏感图片无法自动识别，使用前请考虑当前剪贴板内容。
- 开启剪贴板监听不会读取现有剪贴板，之后新复制的图片才会处理。
- 使用本应用复制不会再重复挂一张图。
- 区域截图会短暂将当前虚拟桌面保存在内存中，仅所选区域写入磁盘；取消不保存。
- 移除/淘汰/清空只删除记录，不删除文件。**收件箱没有自动清理**，需要时从托盘打开收件箱手动管理。
- 日志只记录异常类型和堆栈，不记录图片、剪贴板内容或文件路径。

## 与原版的差异 / 当前限制

- 没有 macOS 的系统 Markup、压感 Quick Look、原生截图接管、录屏缩略图或视频剪辑。
- 内置基础标注/裁剪编辑器，保存为副本；不是专业图层编辑器，暂不提供录屏剪辑。
- 拖拽始终复制，不自动把文件移出收件箱；不同应用对文件拖入/图片粘贴的支持不同。
- 保留细绳、杏橙夹子和略微倾斜的悬挂截图；使用同一套原创小照片 Logo、纸片按钮和数量标签，无全宽不透明底板。透明空白区域返回 `HTTRANSPARENT`；卡片/按钮仍可操作。
- 收起后栏窗口隐藏，仅保留 120×68 DIP 的迷你照片入口；截图时入口也隐藏，避免被截入。
- 主动展开和内置截图结果不自动收起，需点击“收起”或按 Ctrl+Alt+T；悬停展开仍自动收起。
- 自动展开时遇到全屏应用会隐藏；主动启动/快捷键唤出不被全屏检测立即抹掉。独占全屏/受保护桌面无法保证截图。
- 已实现多屏定位和 DPI 感知，但不同 DPI、负坐标显示器、显示设置变更仍需人工回归。
- 快捷键固定；被占用时使用托盘菜单。没有安装器、代码签名和自动更新。

## 开发与构建

需要 Windows、[.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)、PowerShell 7。

```powershell
git clone https://github.com/ThousandOfWind/snapline-windows.git
cd snapline-windows

# 核心测试 + UI 启动/渲染/退出 smoke test（只用生成的测试图片）
./scripts/Test.ps1

# 测试并生成自包含 x64 免安装 ZIP
./scripts/Build.ps1

# 普通程序正在运行时，输出到独立版本目录，不覆盖正在使用的 EXE
./scripts/Build.ps1 -OutputDirectory artifacts/Snapline-0.1.12-win-x64

# ARM64 可构建，尚未在 ARM64 机器上验证
./scripts/Build.ps1 -Runtime win-arm64

# 较小的依赖框架包（运行时需 .NET 10 Desktop Runtime）
./scripts/Build.ps1 -FrameworkDependent

# 真实桌面窗口 E2E（先从托盘退出 Snapline；测试会用生成图片替换剪贴板）
./scripts/E2E.ps1

# 隔离的动画/渲染检查（不读取剪贴板、不注入键鼠，可与普通实例共存）
./scripts/Test-Motion.ps1

# 修改图标后重新生成原创图标
./scripts/New-Icon.ps1
```

测试程序无需第三方测试框架：`dotnet run --project tests/Snapline.Tests -c Release`。
GitHub Actions 的 Build Windows 提供验证用 ZIP artifact。Release Windows 在推送版本标签或手动选择已有标签时，
验证标签/合并来源、测试、打包、校验 EXE 启动，随后发布下载包与 SHA256/源码 manifest；不部署应用。
流程见 [docs/RELEASING.md](docs/RELEASING.md)。

### 项目内测试 skill

[`.pi/skills/snapline-test/SKILL.md`](.pi/skills/snapline-test/SKILL.md) 封装了测试流程、

```text
/skill:snapline-test 测试新增的拖拽功能，扩展回归用例并记录结果
```

若当前 Pi 会话的工作目录不是本项目，可直接要求助手读取上述 `SKILL.md`，
